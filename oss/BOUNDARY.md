# 开源分支许可边界（Clean-Room 规则）

本文档是本分支不可违反的红线。任何新增代码、文档、脚本在合入前都必须符合以下规则。

## 目标

复刻源项目**闭源部分**（路由器端程序、客户端 App）的**公开可观察行为**，
形成独立的开源实现。行为规格只允许来自公开资料：
上游 README、release notes、docs、使用说明视频中演示的功能与交互。
架构不必照搬源项目（Node+Go），用自己的实现达到同样的用户可见功能即可。
源项目中纯属授权/验签/防改的机制（Ed25519 验签、激活码、功能权限检查、入口完整性检查）
**不在复刻范围内**——开源软件不需要它们。

## 绝不做的事

1. **不复制、不分发、不打包** Open-Box 闭源二进制与混淆产物，包括但不限于：
   `panel/server/index.mjs`（混淆 bundle）、`panel/server/native/openbox-core`、
   `panel/dist/` 构建产物、`libobmadvise-*.so`、四个客户端 App 安装包。
2. **不反编译、不反汇编、不逆向**上述闭源实现，不尝试恢复其源码或绕过其授权机制
   （Ed25519 验签、激活码、功能权限检查等）。
3. **不制作换名 / 重打包的衍生产品**（上游专有许可明确禁止）。
4. 不把第三方组件改换许可：sing-box 保持 GPL，zashboard 基座保持 MIT，LICENSE 随包保留。

## 允许做的事

1. 使用、修改上游**公开部署脚本**（`scripts/`）用于自己的部署——上游专有许可第 2 条明确允许。
2. 使用上游官方 Release 公开的 **GPL 组件源码**（如 `sing-box-1.14.1-openbox-tcp23-source.tar.gz`），
   按 GPL 使用、修改、再分发。
3. 使用 MIT / BSD / Apache 等宽松许可的第三方组件（zashboard、Node.js、Go x/*、Geo 数据等），保留原始许可声明。
4. 以**公开文档**（上游 README、release notes、使用说明视频中演示的行为）作为功能规格，
   独立重新实现。功能思想、操作流程不受著作权保护；**实现必须自己逐行写**，
   不得对照混淆产物逐段"翻译"。
5. 参考 sing-box 官方文档的配置 schema（开放标准）。

## 本分支成分清单

| 成分 | 来源 | 许可 |
|---|---|---|
| `oss/core/` 等新增代码 | 本分支独立编写 | MIT |
| 部署脚本（如有修改） | 上游公开脚本修改 | 按上游许可允许范围 |
| sing-box（含魔改源码） | 上游 Release / 官方仓库 | GPL（保持） |
| 面板前端基座（后续） | zashboard | MIT（保持） |
| Node.js / Geo 数据 | 官方渠道 | 各自许可 |

## 命名说明

"OpenBox-OSS" 为分支内工作标题，最终产品名发布前由仓库所有者确认，
避免与上游品牌冲突。
