## 二、内核升级分析（tcp25 → tcp28）

### 变更内容（3 个内存修复）

1. **tcp26**：未在 release notes 中明确说明内核变更（v0.1.335 主要讲故障转移 UI）
2. **tcp27**（v0.1.336）：修复 WireGuard 闲置连接长期保留大块接收缓冲
3. **tcp28**（v0.1.337）：降低 TCP 长连接空闲时内存占用，及时释放闲置读取缓冲

### 评估

- **性质**：纯内存优化，无功能变更，无协议变更
- **风险**：低。VPS 当前内存使用正常（截图显示内存占用 0B，属显示问题），无 WireGuard 节点
- **必要性**：中低。如果 VPS 内存充足且无 WireGuard，可暂缓
- **注意**：仍无 mihomo/1.19.0 版本伪装（原版也无，此为已知无解项）

### 3.2 需要跟进（按优先级）

#### 🔴 P0：v0.1.340 直连旁路 bug 修复

**上游问题**：终端分流里有一台设备指定走代理后，其他设备的直连域名也全部进内核（#553）。

**开源版现状**：我们的 `entry_plan.py` + `transparent.py` 刚实现入口绕过（2026-10-19），**很可能有同样 bug**：
- 当前逻辑：只要有一台终端走代理，是否整个 nftables 旁路被禁用？
- 需要检查 `transparent.py` 的 `entry_mode` 生成逻辑

**建议**：优先排查修复，与上游 v0.1.340 对齐。

#### 🔴 P0：v0.1.341 直连 IP 段入口旁路

**上游变更**：
- 站点集/前置分流的 `ipCidr` 和直连 `geoip` 集合，命中后不再进内核
- 终端分流指定走代理/拒绝的终端仍全部进内核（不受旁路影响）
- 规则页"业务入口"显示直连 IP 判断

**开源版现状**：
- 我们的入口绕过只处理了**域名**（blacklist/whitelist 模式 + direct-answer 集合）
- **IP CIDR 和 geoip 的入口旁路未实现**
- `transparent.py` 的 `obx_entry4` set 只含域名解析结果，不含静态 IP 段

**建议**：实现 IP 段旁路：
1. 从 action=direct 的站点集/前置规则收集 `ip_cidr` 和 `geoip`
2. 生成 nftables set（如 `obx_direct_ip4`），在入口规则中放行
3. 终端分流的 proxy/reject 终端排除在外（仍进内核）

#### 🟡 P1：v0.1.332 内容过滤"恢复默认"

**上游**：内容过滤新增"恢复默认"按钮，可离线恢复三份内置规则。

**开源版现状**：我们刚重构为规则集管理器（`cf_rulesets` 表），但：
- 未预置默认规则集
- 无"恢复默认"功能

**建议**：暂缓。等用户确认内容过滤的最终形态（是否预置规则集）后再做。

#### 🟡 P1：v0.1.335 故障转移测速入口

**上游**：故障转移统一使用组右上角测速入口，完成整组检测和线路切换。

**开源版现状**：我们的故障转移组在代理页节点 Tab 显示，但右上角无测速入口。

**建议**：在代理页节点卡片的故障转移组上加测速按钮，调用现有 `/api/openbox/failover/recheck`。

#### 🟢 P2：其他

- v0.1.334 TUN 放行规则：我们是 Debian 非 OpenWrt，不适用
- v0.1.334 配置文件 0600 权限：可顺手做（`apply.py` 写入时设置）
- v0.1.334 TLS 证书校验：检查 `node_to_outbound` 是否透传 `insecure` 选项
- v0.1.335 内存显示 RSS：概览页内存显示可改为读 `/proc` RSS
- Geo 数据更新：1,917 → 1,919，可更新 `geodata.ts`（我们刚补到 1,787 项，v2fly 最新 1,548，数字对不上是因为上游含子集如 `google@cn`）

## 四、升级方案建议

### 方案 A：分阶段跟进（推荐）

**第一阶段（P0，约 1-2 天）**：
1. 排查修复入口绕过的终端分流 bug（对标 v0.1.340）
2. 实现直连 IP 段入口旁路（对标 v0.1.341）
3. 升级内核 tcp25 → tcp28（内存优化，低风险）

**第二阶段（P1，按需）**：
4. 故障转移组测速入口
5. 内容过滤"恢复默认"（待用户确认形态）
6. 配置文件 0600 权限、TLS 证书校验透传

**不跟进**：
- OpenWrt 相关（TUN 放行、模拟 LAN）
- 客户端更新（仍为 v0.1.330，无变更）

### 方案 B：仅升级内核

如果用户只想升级内核：
- 从 GitHub Release 下载 v0.1.341 的 kernel 组件（tcp28）
- 分块传输覆盖 `/usr/local/bin/sing-box`
- 验证 `/version` 输出 `1.14.1-openbox-tcp28`
- 风险低，约 30 分钟
