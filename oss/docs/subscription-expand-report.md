# 订阅卡片展开查看节点状态 - 分析报告

**日期**: 2026-10-19
**需求**: 对标原版，点击订阅卡片可展开查看该订阅下各节点状态

## 原版行为（用户截图）

- 点击订阅卡片头部展开/折叠
- 展开后显示该订阅所有节点的网格
- 每个节点卡片显示：
  - 节点名（如"良心云 | 日本-09"）
  - 协议（如"vless / udp"、`hy2 / udp`）
  - 延迟徽章（如"53"，颜色编码）

延迟颜色（与现有代码一致）：
- `< 300ms`: 绿色（text-success）
- `< 800ms`: 黄色（text-warning）
- `>= 800ms`: 红色（text-error）

## 现状差距

| 功能 | 原版 | 开源版现状 |
|------|------|------------|
| 卡片点击展开 | ✓ | ✗ 无 |
| 节点网格显示 | ✓ | ✗ 无 |
| 节点协议显示 | ✓ | ✗ 无 |
| 节点延迟显示 | ✓ | ✗ 仅有彩色圆点（node_dots） |
| 延迟颜色编码 | ✓ | ✓（圆点已有绿/黄/红） |

## 数据接口（均已存在，无需后端改动）

| 接口 | 用途 |
|------|------|
| `GET /api/subscriptions/<sid>/nodes` | 获取订阅下所有节点（含 tag、protocol、server 等） |
| `GET /api/health` | 获取节点延迟（`{tag, latency_ms, ok}`） |

## 实现方案

### 前端（SubsTab.vue）

1. **状态**：
   - `expandedSubs: Set<number>` - 已展开的订阅 ID 集合
   - `subNodesCache: Record<number, any[]>` - 订阅节点缓存
   - `subHealthCache: Record<string, number>` - 节点延迟缓存（tag -> ms）

2. **交互**：
   - 点击卡片头部（名称区域）切换展开/折叠
   - 首次展开时并行加载节点和延迟数据
   - 延迟数据复用 `/api/health`，按 tag 匹配

3. **UI**：
   - 展开区域：网格布局（`grid grid-cols-2 sm:grid-cols-3 md:grid-cols-4 lg:grid-cols-5 gap-2`）
   - 节点卡片：圆角边框，名称截断显示，协议小字，延迟徽章右下
   - 延迟颜色：`<300` green、` <800` yellow、其余 red、无数据 gray
   - 展开/折叠图标：`▾` / `▸` 在卡片头部

4. **性能**：
   - 节点数据按订阅缓存，切换展开不重复请求
   - 延迟数据每次展开时刷新（保证新鲜度）
   - 复用现有的 `speedTest(s)` 按钮刷新延迟

### 不改动项

- 后端 API：全部已存在
- 卡片拖动排序：保持
- 现有按钮：保持（启用/停用、测速、刷新、编辑、删除）
- 节点状态圆点：保持（折叠时仍显示）

## 验收标准

1. 点击订阅卡片头部展开，显示节点网格
2. 每个节点显示名称、协议、延迟
3. 延迟颜色编码正确
4. 再次点击折叠
5. 切换订阅不重复请求节点数据（缓存生效）
6. 延迟数据为最新（每次展开刷新）
