# 六阶段对标完成报告

**日期**: 2026-10-19
**范围**: 面板 + 路由器核心闭源功能对标（客户端除外）

---

## 阶段1：规则穿透/调试 ✅ 完成

**实现**:
- 新建 `oss/core/penetration.py`：穿透匹配逻辑（前置规则 → 站点集 → 兜底）
  - 域名匹配：domain/domain_suffix/domain_keyword
  - IP 匹配：ip_cidr（IP 只管 IP，域名只管域名，符合原版不变量）
  - 返回：命中来源、规则详情、出口、DNS 服务器、解析 IP
- 增强现有 `POST /api/openbox/penetration` 端点（原仅查站点集，现支持前置规则）
- 前端：目标分流页顶部新增"规则穿透测试"卡片，输入域名/IP 显示命中规则、出口、DNS

**验证**: VPS 实测 `google.com` 返回正确（兜底 → 所有-自动）

**诚实缺口**: 原版还支持"实际发起请求查看真实线路"，我们仅做规则匹配预览，未做真实连接测试。

## 阶段4：终端分流验证 ⚠️ 受限

**状态**: 代码已完整（三策略 + nftables 生成），但 **VPS 无 LAN 环境**，无法做真实终端流量验证。

**需用户配合**: 在真实路由器/LAN 环境测试：
1. 设一台终端走 proxy，检查 `source_ip_cidr` 路由是否生效
2. 设一台终端走 direct，检查 nftables early accept
3. CRUD 后是否自动应用

## 阶段5：入口绕过 ⚠️ 框架完成

**实现**:
- `scheduler.py` 新增 `_maybe_observe_direct_answers()` 框架，每 60s tick 调用
- 数据层（`direct_answer.py`）已就绪：TTL 钳制、过期清理、DB 持久化

**诚实缺口**:
- 实际 DNS 日志解析逻辑未完整实现（需结合站点集判断直连域名，复杂度高）
- geoip 直连集合展开为 CIDR 未做（需 geoip .srs 数据解析）
- 规则页"业务入口"显示直连 IP 判断未做

**原因**: 完整实现需在 DNS 路径内钩子写入（原版 Go 核心行为），面板端只能做近似（异步日志扫描），投入产出比低。
